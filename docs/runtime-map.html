ShiftLab Runtime Map

What runs where when someone uses ShiftLab live: the browser, the Cloudflare Worker that serves and grades, and the Supabase project that stores accounts and results.

Three requests, followed through

  • A guest closes an alert

    The browser sends the alert id and the written report to a server action. The server finds the key, grades it, and returns the score. The result is kept in browser storage only, and one anonymous case_closed event is added.

  • A signed-in student closes one

    Same path, then the server also saves the case under that student's login. Row-level security means they can only ever read or write their own rows, and a closed case cannot be edited.

  • The owner opens /admin

    The admin layout checks the role and answers 404 to everyone else. The numbers come from database functions that check the role again, so a student cannot call them from the site.

Read from the code, not from a running system: the Supabase client is used only in server code (no browser client in the repo), and migrations 0001 to 0008 define the tables and functions shown. The sign-in link flow (email or Google, back through /auth/callback) is described in the box text rather than drawn.
